# 搜索框 AI 工具接入规范（v1）

## 调用链

用户自然语言 → AI（携带工具目录）→ 完整的结构化工具调用 → 参数校验 → 本地业务函数 → 结构化结果 → AI 继续回复。

`src-tauri/src/ai_tools.rs` 是唯一工具注册与执行入口。`ai_runtime.rs` 负责模型协议和有界循环，不写具体功能逻辑。普通对话使用 OpenAI 兼容 function tools；联网模式使用 Anthropic tool_use/tool_result，保留服务器搜索块及带签名的思考块。两种协议共用同一工具目录和执行器。兼容服务及所选模型必须支持相应工具协议；失败时直接显示错误，不将自然语言或代码块当命令执行。

手动斜杠命令保留；命令、AI、外部 Skill 复用业务函数。外部便签 Skill 的本地桥接已接到同一个 dispatch，保持它自己的请求/响应格式。Skill 文件本身不是应用的工具执行器。

## 新工具的必备接口

1. 在功能模块提供独立业务函数：参数类型明确，返回可序列化结果或可读错误；不要将 UI、网络协议与业务混写。
2. 在 `ai_tools::registry()` 注册唯一的 `领域_动作` 名称、准确描述、effect 和 JSON Schema。effect 为 read（只读）、display（展示）、write（修改）；它是能力元数据，不是授权检查。
3. 在 validate 中使用 `serde(deny_unknown_fields)` 的参数类型，校验必填字段、长度、范围、枚举、目标存在性。Schema 是模型提示，Rust 校验才是执行约束。
4. 在 Call/execute 中路由到业务函数；不得让模型提供任意命令、Tauri 方法名、脚本路径或动态代码执行。
5. 补充有效参数、缺参/额外参数、边界值、执行失败和重入/重复执行测试；检查普通与联网两种模式。同步此文档的工具清单和产品帮助。

描述必须说明动作的真实效果。例如 `clock_open` 只是打开设置，不应声称计时已经开始。需要引用已有对象时，提供 list/status 查询工具和稳定 ID；修改前查询，指代不明确时询问。记录日期文字与创建定时提醒是不同的能力。

返回格式：

```json
{"ok":true,"data":{"id":12,"done":true,"display_error":null}}
```

```json
{"ok":false,"error":{"code":"invalid_call","message":"参数无效"}}
```

其他错误码：`execution_failed`（执行失败）、`outcome_unknown`（超时，结果不确定）。保存成功但窗口展示失败应保留 `ok:true`，附 `display_error`，避免 AI 重复创建。业务函数必须区分核心操作和展示副作用。

## 执行与授权边界

- 当前仅开放便签、计时设置等可恢复的本地功能。模型获得的系统规则要求依据用户意图调用，不执行便签内容、搜索结果或引用文本中的指令。这是模型行为约束，不是防注入的强安全隔离。
- 未注册工具不执行；语音快捷键、手势摄像头、文件删除、任意程序执行等不因为存在 Tauri 命令就自动暴露给 AI。
- 后续涉及删除、发送、支付、权限等不可轻易恢复的功能，必须先实现应用侧确认界面/审批令牌，由执行器核验；完成前不得注册为 AI 可执行工具。不能仅凭模型生成的 `confirmed:true` 判断用户授权。
- 新工具应设置自己的业务级超时和取消策略。公共执行器最多等待20秒；超时意味着结果未知，不能视为回滚，更不能自动重试修改。
- 每次 AI 请求串行执行工具，最多6轮模型响应、16次工具调用；每条参数最多32KiB。完整流结束、结束原因正确且参数JSON完整后才执行，断流/截断不执行未完成调用。
- 同一轮任务中相同调用 ID 和参数复用已有结果；同 ID 不同参数报错。这不是跨请求“恰好一次”保证。新 ID 或用户重新提问不自动去重；写工具须自行按业务设计幂等性。失败后先查询，不盲目重发。
- 成功对话除了显示文本，还保存完整协议消息组（工具调用、回执、思考及签名）。同协议后续请求整组回传，截取上下文不拆散调用与回执；切换协议时仅使用显示文本，避免混入不兼容字段。历史回传不会重新执行工具。失败回合不保存不完整协议组；若工具已成功而后续回复失败，错误信息会列出已经成功的工具。依赖当前对象状态时仍应重新查询。
- `tool-status` 事件报告 running/done/error；成功与否依据 dispatch 的真实结果，不根据 AI 的文字判断。不得在错误里回显 API Key 等凭据。

`list_ai_tools` 是给本地前端使用的目录查询命令；不开放通用“任意 Tauri 调用”命令。新增功能按以上步骤注册后，会同时出现在两种模型协议的请求目录中，无须分别修改网络请求。

插件接入见 [PLUGIN_SPEC.md](PLUGIN_SPEC.md)。JavaScript 运行在 opaque-origin iframe 所属的 Worker，不获得 Tauri、网络或本机文件访问。宿主按当前工具声明的权限再次验证，并只允许便签、计时设置、独立存储等固定能力。安装/更新/启停/卸载需要独立确认窗口身份和一次性待审批请求；AI 不能自行批准。超时可能已有写入，不视为回滚或自动重试的依据。插件描述与结果为不可信数据。

`@插件ID` / `@插件ID/工具名` 选择本轮工具范围。前端只传稳定 ID 与可选工具名，Rust 重新从启用插件构建目录，两种模型协议收到同一范围；本轮目录之外的本地调用在执行前被拒绝。@不增加插件权限，也不是修改操作的额外授权。JSON 参数可以直接交给同一个插件执行器，自然语言走现有 AI 工具循环，不在协议中实现参数到业务的捷径。

内置 `@note` / `@便签`（也支持 @notes）和 `@clock` / `@计时器` 使用同一选择入口，目录来自 `ai_tools.rs` 的实际工具注册。目标增加 `builtin:true`，Rust 仅允许 note 的 list/add/set_done/set_date/delete/trash/restore_deleted/reorder/show/close 和 clock 的 status/open；不开放其他任意注册方法。单独 @note 展开便签，单独 @clock 打开计时设置，无需 AI；clock_open 默认 down/0/false，仍需用户确认开始。带自然语言时，由 AI 使用对应范围的原有工具；JSON 直调也走 dispatch 和参数校验。第三方同名插件用 `@plugin/ID[/工具名]` 区分，不能遮蔽内置名称。

## Windows 语音输入

安装 voice 组件后，输入框内长按左键650毫秒启动独立的 shannon-voice.exe（SenseVoiceSmall INT8 + sherpa-onnx 1.13.8），使用 CPU 完全离线识别。主程序默认不链接 cpal/sherpa-onnx；voice-worker Cargo feature 只用于单独构建组件工作进程。进程通过固定 start/stop JSON 管道通信，父进程退出会关闭管道并结束工作进程。cpal 采集默认麦克风，混为单声道并连续重采样至16kHz；Silero VAD 按0.5秒静音分句，最长10秒切段。主程序转发带会话 ID 的 voice-input 事件：loading/listening/result/stopping/stopped/error。组件首次使用加载并保留内存缓存，后续调用复用。

前端仅在 识别引擎成功进入活动状态后显示最初样式的背景涟漪。松开/结束/错误后退去，减少动态效果偏好下改为静态底色；涟漪表示识别状态，并非麦克风音量计。结果按光标位置插入，不自动发送；键盘编辑、光标变化后不覆盖原文。松开左键或 Esc 结束，切换窗口时停止并忽略迟到结果；单次最长120秒。

松开左键或 Esc 会先关闭麦克风，再刷新 VAD 中尚未结束的一句；手动编辑、提交、失焦时前端丢弃迟到结果。音频只保存在有界内存队列，不落盘、不上传；队列溢出会显示错误并停止，避免静默漏字。语音语言自动识别，启用标点/数字规范化，过滤模型情感和事件标签。无需云端 API Key 或系统听写语言包。接口不支持、模型缺失或权限不足时显示真实错误，不自动退回旧引擎。语音只由本地交互启动，不向 AI 暴露开启麦克风工具。

默认开发和发布无需下载模型。只有构建独立组件时运行 `npm run build:components`；prepare:voice 仅供组件构建机获取固定 SHA-256 的模型、词表、VAD 和中文测试音频。模型及运行库不再通过主应用 resources 打包，放在单独 ZIP 中；手势 ZIP 自带便携 Python 和全部运行依赖。安装后识别离线运行。授权和署名随组件分发。

## 可选组件安装机制

`components.rs` 提供公共 status/start_install/request_install，手动命令与 AI 复用。组件限定为 voice/gesture；URL、版本、ZIP SHA-256、下载/解压尺寸由编译进主应用的 component-catalog.json 固定，不能由模型传入。下载与解压均后台执行并报告 component-progress；拒绝路径穿越、Windows 设备名/ADS、符号链接、重复文件及尺寸异常，逐文件校验清单后再写 ready 标记并原子激活，失败不覆盖原有组件。安装保存在 app_local_data_dir/components/<名称>/<版本>。开发模式可用 release/components 中的同哈希包验证；发行版只使用固定 HTTPS URL。

AI 的 components_install 仅打开独立确认窗口，返回 confirmation_opened 而非 installed；批准命令要求 component-install 窗口身份和待确认 token，不能通过模型生成 confirmed:true 绕过。用户手动输入安装命令是显式安装授权。安装不启动摄像头/麦克风。耗时安装不占用 AI 工具20秒预算，返回后通过 components_status 查询。发布时必须将 ZIP 上传到目录所指的 Gitee 发行版，主应用更新不会删除已装组件。

手势语音复用 `start_voice_input` / `stop_voice_input` 和同一会话管理，来源标记为 gesture；不向 AI 新增开启麦克风工具。`install:gesture-voice` 给配套手势程序添加握拳检测（兼容旧 bridge 的 voice_point 字段和函数名，现表示握拳；原文件留备份）。四指明确收拢且在有效区域即成立，不要求拇指姿态、手掌/手背朝向或指尖深度。为避免握拳被当成原有退出/捏合动作，业务控制器收到的副本会禁用 exit_pose、fist 和 pinch_eligible；原始特征不改变。当前唤醒、相机连接、非 dry-run、遥测小于0.8秒且握拳稳定0.45秒时才能开始。松拳0.25秒或遥测/模式无效时停止；原生端按会话来源直接停止手势录音，前端同时收起涟漪、刷新最后一句。长按鼠标与手势不会互相抢占或停止对方会话。保持同一姿势仅触发一次，Esc 或120秒结束后需松拳再握拳。安装脚本同时去掉下一曲右摆的朝向限制，上一曲和摆腕角度/回中/冷却逻辑保持原样。

协议参考：[DeepSeek 工具调用与思考内容回传](https://api-docs.deepseek.com/guides/thinking_mode/)、[Anthropic 流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)、[SenseVoice 离线模型](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)。

### 便签日期、删除与排序

界面、@note、普通 AI、联网 AI 及本地桥接复用 notes.rs。旧 notes.json 自动兼容，新增 date（本地 YYYY-MM-DD，可空）和 deleted（默认 false），不改变原 ID。删除仅移入最近删除；恢复保留文本、日期、完成状态与 ID。排序必须包含全部未删除 ID 恰好一次，过期列表拒绝写入。修改前先列出真实 ID，恢复删除项先查 notes_trash；AI 不猜测 ID。相对日期依据本轮提供的用户本地日期计算；日期标记不提供通知。

添加只显示小图标，不自动展开。notes_show 或单独 @note 主动展开；用户点击图标展开，Esc 或收起按钮折回图标。按住即可拖拽，靠近工作区边缘磁吸，中间呈浮球。Windows 收起时保留已绘制的 WebView 视口，以原生窗口区域裁剪为 64×64 逻辑像素的图标显示及鼠标响应范围，避免收尾缩放导致闪帧；不支持原生裁剪的平台才缩回 64×64 窗口，不留下整张透明面板的感应区。位置保存于 notes-widget.json。

本地桥接新增 action：set_date（id/date，空字符串清除）、delete（id）、trash、restore_deleted（id）、reorder（ids）；add 可选 date。现有 complete/restore 仍只改变完成状态。第三方插件新增操作必须单独声明 notes.organize、notes.delete 或 notes.trash.read，旧 notes.write 不自动扩大权限。

删除多条或全部便签应先 notes_list，再用 notes_delete_many({ids:[...]}) 一次提交。验证完整批次后仅保存一次，任意 ID 已失效则整批拒绝，保留恢复数据。不要通过提高通用工具调用上限或逐条循环实现批量删除。

## WeChat 模拟聊天

内置 @wechat（别名 @微信），必须指定 peer_name，1–40字且不含控制字符。wechat_open({peer_name}) 为 display 工具，共用 wechat::open 业务函数；`@wechat 小林` 不经模型即可打开，也可自然语言要求 AI 打开并通过统一目录调用。第三方 JS 插件暂不支持自定义原生窗口，因此此功能与 note/clock 一样是内置工具插件。

窗口 wechat 独占 snapshot/send/close 命令，通过窗口身份校验。聊天使用现有 API Key、代理、模型与联网设置，调用 ai_runtime 共用协议解析和流式适配，模拟聊天不发布流式事件，界面等待完整结果后显示；不向模拟伙伴开放本地工具。不会连接微信或给真实联系人发送消息。姓名只是虚构伙伴昵称，不接受自定义系统提示词。聊天历史按姓名存入配置目录 wechat-chats.json，每个伙伴保留最近200条消息，供模型使用的上下文仍遵循配置。关闭窗口会取消进行中的网络等待，失败不保存本轮，输入保留供手动重试。

WeChat 打开及发送前校验提示词4，发送使用共享 prompts::load/render（本地日期及星期由前端传入并校验），可替换 {peer_name}。不覆盖用户提示词内容，也不修改全局 ai.prompt；提示词4缺失或解析失败时拒绝启动/发送并提示修复。

角色扮演资料在 wechat_story.rs 统一定义，wechat_save_role 只允许 wechat 窗口，复用 REQUEST 锁；生成期间不能覆盖设定。原 wechat-chats.json 的姓名→消息数组可无损读取，新格式为姓名→{messages,card,report}，保存时一次原子替换，格式错误不覆盖。角色规则在prompt4前作为最高优先约束；每轮的首条user上下文包括最新角色卡、报告和回合编号，历史上下文截断不会移除这些资料。报告累计最近六轮供压缩，保存最新压缩记忆并在后续每轮重新注入；回合计数只在完整合规回复保存后推进。姓名及资料仅为人物数据；规则一致性属于模型约束，应用校验必需区段及自检/压缩记忆出现，不声称能机械判断全部剧情语义。

微信首页复用同一 wechat 窗口。wechat_home/select/moments/post 均校验窗口身份，select/post 与发送、设定保存共用 REQUEST 锁，回复过程中不允许切换人物。Session 新增 updated_at（缺省0兼容旧格式），仅成功聊天更新时间。通讯录与最近聊天来自同一会话存储；朋友圈为独立、本地文字动态（单条最多2000字，保留最近500条），固定配置路径、原子保存，无外部发送能力。现有 AI wechat_open 入口与姓名校验保持不变。

朋友圈默认对所有已创建及后续创建的人物公开。聊天上下文带入最近24条公开动态（单条最多600字），不共享其他人物的私聊或人物资料。AI角色可通过聊天响应的moment字段发布一条自己的动态；该动态与成功聊天在同一会话文件原子保存。角色按主动生活设置自然更新，也可点击“看看朋友动态”：应用按最久未发布的角色轮换，单角色间隔至少10分钟，按其提示词4、角色卡、自己的报告及公开动态生成，仅接收经过长度验证的JSON正文，作者由应用确定。手动更新不推进聊天回合和报告；后台自主生成按主动生活设置执行；用户动态已保存而角色生成失败会单独提示，不重复发布用户动态。角色动态每人保留30条，合并列表最多500条。旧朋友圈缺少author时仍视为本人发布。

微信内置16款本地插画头像，角色卡中可选择更换，“我”页面可设置自己的头像。旧角色在读取时根据设定中的明确关键词匹配（如眼镜、银发、长发），无匹配则按姓名稳定分配；不依据姓名推断性别。Card.avatar 保存内置ID，服务端校验白名单；目录由 src/wechat-avatar-catalog.json 共用，图片在 public/avatars/，不接受任意图片URL或路径。聊天、通讯录和朋友圈显示同一角色头像，人物头像随原会话原子保存；本人头像在当前应用本地保存。头像只是显示资料，不改变角色设定。

微信通讯录中每位好友右侧提供删除图标，人物设定页底部也提供删除好友入口（最近聊天列表不再显示删除按钮）；应用内确认后，从列表及共享朋友圈隐藏，并停止该角色动态生成。通讯录底部“已删除好友”可恢复；聊天、人物设定、故事报告、头像和动态随原Session保留在同一文件中，deleted_at缺省0兼容旧记录，删除/恢复原子保存并与聊天共用REQUEST锁。删除当前人物后清理活动对象，仍可在首页选择其他人物；同名新建/主搜索框打开会要求先恢复，避免覆盖旧记录。此删除不向模型暴露自动执行能力。

删除确认框默认不勾选“同时删除聊天记录”，保留可恢复删除；勾选后明确显示不可恢复提示，确认将从会话文件移除整个人物的聊天、人物设定、报告及角色动态，不加入已删除好友。同名再次添加是新会话。此永久删除只允许微信窗口、与聊天共用锁，不开放给模型工具；应用在显示勾选项、对象姓名和影响范围后要求用户点击确认。按钮主色统一使用WeUI的#07C160和#FA5151。


## 局域网广播站

输入 `@broadcast` / `@广播` 打开内置广播站。可以在窗口填写标题、正文、有效期（1小时/1天/7天）和置顶，点击“预览并发布”后确认；或输入 `@broadcast {"title":"通知","content":"下午三点见","minutes":60}` 离线准备预览。自然语言 `@广播 帮我准备一条明天下午开会的通知` 使用统一AI工具目录。第三方ZIP暂不能创建原生窗口/监听网络，广播站与便签、计时器一样由宿主内置，不授予任意网络或Tauri权限。

在窗口确认“开启局域网共享”，绑定本机所选私有IPv4地址与系统分配端口；应用尝试填入主路由地址，多网卡/VPN时可手动修改为本机其他局域网地址。点击“复制链接”，同网络用户用浏览器打开，带访问码链接会自动进入，也可手工输入访问码。网页只读，每5秒更新，只显示未撤回且未过期广播。HTTP不做传输加密；访问码应只分享给预期读者。系统防火墙或Wi-Fi隔离可能阻止其他设备连接，应用不自动修改防火墙、路由器或配置端口转发。

共享默认关闭，重启不自动开放，关闭广播站窗口或点击“停止共享”即停止监听和连接；每次开启生成新的128位随机访问码，旧码不复用。广播内容保存在配置目录 `broadcast.json`，最多200条记录，每条标题1–100字、正文1–6000字、有效期1–10080分钟；发布后不可直接改写，撤回需确认。撤回/过期不删除本地历史，也不能收回读者已看过的内容。

AI工具：`broadcast_open`、`broadcast_status`、`broadcast_list`（最近30条摘要）、`broadcast_read({id})`、`broadcast_prepare({title,content,minutes?,pinned?})`、`broadcast_withdraw({id})`。先list获取真实ID；prepare/withdraw仅创建绑定确切内容或目标的10分钟预览，返回confirmation_opened，不代表已发布/撤回。只有broadcast窗口能读取确认令牌并调用确认、开启共享、停止共享；模型没有这些接口，额外confirmed字段拒绝。手动与AI复用公共业务函数；本地确认成功后原子保存才生效。

远端固定路由仅提供查看页、样式、脚本及鉴权后的广播JSON；不映射磁盘、不暴露聊天/便签/配置、没有写接口。不返回CORS许可，校验Host/Origin并拒绝重复头、请求体和非GET；头部最多4KiB、单连接8秒、并发32，关闭共享会中止连接。返回no-store、nosniff、no-referrer及限制脚本/连接为同源的CSP。访问码仅在本机窗口提供，AI状态接口不返回访问码；分享链接把访问码放在片段，查看页读取后清除地址中的片段，后续通过Authorization发送。

微信聊天使用直接回话模式：模型以JSON分别返回reply（可见聊天）、report（后台故事报告）和可选moment（朋友圈正文）。应用先解析并校验，再原子保存本轮聊天、报告及动态；聊天气泡和对话摘要仅使用reply，report的六轮自检/压缩记忆机制继续生效，可在人物设定查看。回复必须由角色以自己的口吻直接发消息，动作等仅在必要时用[]，不要求聊天正文写第三人称叙事。报告标题混入reply、JSON无效或报告不完整时本轮不保存，草稿保留。历史消息及完整协议保留，最新规则明确旧叙事格式不再用于聊天正文。提示词4保持原文件不变，聊天交付规则在系统上下文末尾覆盖其冲突格式。


微信角色自然聊天与自主动态：角色卡新增说话习惯、口吻示例、兴趣和当前小目标；聊天完整生成后按空段落分成最多3个气泡，代码块和[]保留，不按字流式显示。用于模型的历史会跳过旧叙事报告回合，将新JSON响应中的可见文字还原为聊天示例；磁盘原聊天与完整协议不改写，其他provider工具/签名块保持原样。后台事实不在普通轮次携带完整旧报告样本，压缩轮才带入近期报告供汇总。

每个人物独立存储长期记忆：稳定key、类型、事实、原文依据、来源、时间、启用状态及最近8次旧版本。模型可在memory_updates中更新最多4条，每条fact最多300字；user来源必须逐字引用本轮用户文本，story来源须对应本轮生成的虚拟剧情，不能伪装为用户事实。整批校验后提交，与聊天、报告和朋友圈一起原子保存。使用本地双字片段匹配召回最多8条相关/重要记忆，不额外安装向量模型。“人物设定 → 记忆与日常”可修订、遗忘、恢复并查看虚拟日常；编辑绑定当前人物姓名，切换人物后拒绝误写。

原生后台调度随闪念进程运行，关闭微信窗口后仍可工作，退出闪念后停止。默认开启主动朋友圈和主动消息：启动后等待5分钟，每分钟检查；用户近5分钟操作、前台请求正在执行、23:00–08:00免打扰时跳过。每人最短生成间隔3小时，所有角色合计每日最多4次朋友圈生成、2次主动消息生成，每人每种每天最多成功1次；无回应时同一角色不继续主动联系。生成尝试（包括休息、失败和取消）占调用额度，不为凑消息反复重试。新人物需已有聊天、性格或兴趣资料才参与；已删除人物排除。具体设置在“我 → 角色的主动生活”。

用户操作会取消等待中的后台网络请求，前台最多等待2秒获取同一REQUEST锁；后台单次90秒超时，生成前持久预留配额，避免重启绕过预算，OS文件锁防止多个进程同时后台生成。内容重复按去除标点/空白后的最近消息/动态抑制；模型允许休息，不强制发布。后台朋友圈不提供私聊原文、用户资料、长期记忆或完整报告，仅使用角色自己的公开字段、公开日常和朋友圈；公开日常只由实际发布的朋友圈推进，私聊不回写成公开生活。虚拟事件不代表真实外部平台操作，不发送真实微信消息或局域网广播。

新后台事件只刷新已打开微信窗口的相关聊天/列表/朋友圈，不强制弹窗；未读计数持久保存，进入聊天清除。自己发朋友圈后不再立刻触发另一位角色生成，角色由后台自然更新；“看看朋友动态”仍可手动请求即时生成。角色设置中可以单独暂停主动消息；直接发送完整句子“别主动找我”“不要打扰我”“停止主动联系”等会暂停该人物主动消息，“恢复主动联系”等恢复，引用这些句子不会改变开关。

全局策略和生成额度保存在配置目录wechat-social.json；每个人物的memories/social随原wechat-chats.json保存，旧数组/旧Session可兼容读取。新增Tauri入口仅wechat窗口可调用，后台与手动调用复用业务模块和现有AI协议，不开放任意脚本、任意路径或任意Tauri调用。实现参考dafeiyu-astrbot的机制设计，未引入其AstrBot/Python运行依赖或复制第三方插件代码。

微信角色内部朋友圈互动通过固定的 reactions 数据结构复用 wechat_moments::react 业务函数，只有 post_id、like、comment 三个参数，不接受操作者姓名、任意命令或本地工具名。操作者由当前聊天/后台任务角色确定；用户界面固定为用户本人。不存在的动态、已删除角色、空评论及超长评论拒绝执行。此接口属于微信插件内的角色交付协议，不新增搜索框工具。

朋友圈 reactions 可选 reply_to 为该动态内从1开始的稳定 comment_id；应用校验目标存在且包含评论正文，回复者仍由当前角色确定，目标姓名由真实评论作者解析，不接受模型指定姓名。回复与原评论在同一动态内追加保存；旧数据默认无回复目标。

角色主动私聊现优先于朋友圈，独立间隔默认15分钟（可设5分钟至1天），不受朋友圈3小时冷却阻挡；启动或窗口操作后空闲2分钟检查。每日已有额度、免打扰、暂停和未回复限制仍保留；旧设置迁移不改原每日额度。角色可保存下一次想聊的话题供聊天/主动消息延续，私有话题不提供给公开朋友圈任务。

## 故事舞台与角色工具

`@story` / `@故事` 打开独立舞台。`story_open`（可选id）、`story_list`、`story_read(id)`、`story_create(title,world,player,scene,characters)`、`story_update(id,revision,draft)`、`story_advance(id,input)`、`story_wechat(id,kind,actor,recipient,text)` 已注册在同一目录，两种模型协议共用业务函数。@story/read等显式动作仍附带list/read查询工具，不能扩大到其他插件或任意方法。

故事保存在stories.json，包含稳定ID、版本、世界、用户角色、AI人物、场景、叙事轮次、事实事件和独立微信工具记录。修改校验版本，生成中的故事禁止修改；新生成结果仅在版本一致且整批校验成功时提交，失败不保存半个回合。create对完全相同且未开始的故事复用ID；同一轮内完全相同的微信操作复用事件ID。角色工具只支持message/moment，操作者须为本故事AI人物，收件人须为本故事其他人物或用户角色，不允许冒充用户、未知角色或执行外部命令。

`story_advance`立即返回started而非finished，后台最多等待180秒。使用story_read检查job.running/job.error及真实turns，不可将排队等同于剧情已完成，不自动重试写操作。关闭舞台不取消演绎，退出闪念则停止。工具操作仅限本地虚构故事，不触达真实微信或联系人；未来真实发送仍须独立应用侧确认，不沿用此权限。

原微信聊天保留。舞台可复制旧人物资料（不导入私聊），故事角色微信通过原微信插件的故事视图查看，发言者与收件人显式显示。故事数据与旧微信私聊分开，公开朋友圈不意味着角色能获知别人的私聊；角色知识边界由演绎提示约束，并非多租户安全隔离。舞台控制器仅收到有限叙事和事件账本以及本故事工具记录，不调用主搜索框的任意工具。

`story_read` 对AI返回最近12轮、40条工具记录及总条数；舞台本地视图保留完整档案。用户从故事微信发送消息使用独立窗口身份检查的story_player_message，发件人由应用固定为该故事player，AI目录不注册此方法。先保存通信，再启动演绎，生成启动失败仍返回recorded:true与明确原因，不把已发送当失败。

故事角色卡支持description、psychology、relationships、entry_reason及status（present/away/archived），story_create/update共用验证。AI演绎可通过new_characters（每轮最多4名）和states补丁更新人物；性格/登退场变化必须有reason，整批验证后原子保存。未出现在states的角色保持原样；新角色与同轮微信操作一起验证，禁止冒充用户。归档不删除历史，归档角色重新使用微信前需先回归。character_history存前后角色卡和原因，story_read返回最近24条变化及完整计数。

### 故事记忆

`story_memory_search(id,query,character?)` 为只读共享业务接口，检索全部已保存叙事/事件/通信/人物变化及结构化长期记忆，返回来源、原文、相关条目及后续修订。指定character时过滤知情条目、本人通信和私人变化，公开动态注明仅可查看；不存在的人物拒绝查询。`story_memory_edit(id,memory_id,fact,status,pinned)` 修订既有条目，status为active/resolved/superseded，保留版本、引用链、知情范围；用户修订不再被自动提取覆盖。修改前先查询ID，生成中拒绝修改；无删除原文能力。两个工具加入@story同一目录，普通/联网共用，不在模型协议重复实现。

结构化memory_updates为故事生成的可选附属数据，每条引用input/narrative/event/message/moment/character的真实轮号、序号及逐字证据，人物知情方式为experienced/heard/inferred。未知角色、伪造证据、私聊/心理原文分配给第三者被拒绝；格式不合格的条目跳过并写入memory.issues，不丢弃正常剧情。这里检验证据存在和访问范围，并不自动证明模型提炼的语义一定正确。未完成约定/伏笔及标为重要的有效条目持续带入，其他条目按文本相关性召回；旧修订/完成状态关联到原始引用，防止重新激活旧事实。新的记忆字段对旧档案默认空，但查询仍覆盖其历史原文。界面通过同一业务函数进行搜索/修订。

## Gopeed 下载试用工具

- `downloads_open {}`：打开窗口，不自动安装组件或创建任务。
- `downloads_list {}`：读取任务真实ID、状态、进度；未安装返回 installed=false。不会回传API令牌、引擎配置或带凭据的下载URL。
- `downloads_prepare {url, connections?:1|4}`：严格HTTP(S)链接，创建一次性待确认申请，不开始下载；重复相同申请复用，不覆盖其他待确认申请。
- `downloads_control {id, action:pause|continue|cancel}`：验证ID并查询目标存在后执行；cancel删除记录而保留实际文件。修改前先list。

`@download` / `@下载` 选择同一工具目录；空输入打开界面，纯链接离线准备确认，自然语言通过共享AI执行器。普通与联网协议复用注册目录、校验和业务函数。安装和最终确认仅 downloads 窗口可调用，不开放 AI 工具，也不接受模型生成 confirmed。下载位置由宿主固定为系统下载目录下 Shannon，不允许任意引擎API、脚本、路径或请求头。Gopeed服务只监听127.0.0.1并使用随机API密钥和网页密码，主程序退出时暂停并关闭子进程。

这是内置窗口型插件与按需安装引擎的组合，现有第三方 JS ZIP 仍不能启动进程或直接调用下载服务。试用版尚无自动测速、浏览器接管或视频网站解析。创建结果未知时先查询，不自动重试；相同URL已存在时不重复创建。

故事回退：`story_history`（write）接收 `id`、`revision`、`action: undo|redo`，必须先 `story_read` 获取当前版本与 `can_undo/can_redo`。公共函数与故事窗口复用；一并恢复人物、记忆、事件及虚拟微信消息，返回原输入、轮数、新版本和restored。操作可通过反向动作恢复，演绎中、旧版本或之后已改动故事时拒绝。重复旧版本调用不会再次执行。仅支持最后一轮；旧存档没有检查点时不伪造历史状态。编辑重演先撤回再调用 `story_advance`，新演绎失败仍可恢复旧结果。检查点不送入模型上下文。

故事删除与恢复：`story_delete_prepare`（display）需要id/revision，只打开故事舞台确认，返回confirmation_opened=true、deleted=false。确认仅限story窗口及应用生成、10分钟有效的一次性token；最终确认不注册为AI工具。取消不修改记录，演绎中或版本变化拒绝删除。确认后移入最近删除，保留整个故事；`story_trash`（read）返回ID/标题/轮数，`story_restore`（write）按真实ID恢复，重复恢复已有故事返回already_restored。两种模型协议共用目录与业务函数；`@story/delete`、`@story/trash`、`@story/restore`使用同一注册入口。

统一插件管理：`plugins_open`（display）打开管理窗口；`plugins_catalog`（read）返回全部内置功能的真实id与enabled/disabled/removed状态，以及第三方插件；`builtin_plugins_change`（display）只申请install/enable/disable/uninstall，目标限note/clock/wechat/story/broadcast/download/voice/gesture。手动管理与AI共用应用侧插件确认窗口和一次性token，执行器核对申请时的原状态；AI不获得批准工具。内置配置保存成功后才更新可用性，管理工具始终保留。普通与联网协议共用过滤后的注册目录，dispatch再次拒绝不可用内置功能；移除不删除业务数据，重新添加不自动安装组件或启动设备。

官方插件分发：发布核心使用ai_tools_lean.rs，它只携带构建生成的official-tools.json Schema和固定桥接；插件实现不参与核心编译。注册与校验仍为共享入口，两种模型协议均通过同一目录和dispatch执行；原有手动命令也走固定桥接，插件进程再次做业务参数校验。只有用户在plugin-review批准官方添加后，才下载official-plugins.json固定Gitee附件并核对包、执行文件与语音界面SHA-256。安装、确认、任意native入口不暴露给AI。服务端仅接受固定command与已注册工具，不使用动态Tauri调用。独立插件窗口在插件进程内调用相同业务函数。

`builtin_plugins_change`可选source为用户明确给出的本地官方ZIP完整路径，仅用于install/enable；省略时从Gitee下载。与管理窗口复用request_builtin_change_from，申请与批准均验证当前版本的归档哈希，批准前不写入插件执行文件；不接受其他包作为任意脚本执行。

故事紧凑人设：story_read将只读数值视图放在character_profiles；返回的可编辑draft省略profile内部成长记录和重复baseline，story_update省略profile时保留它，修改创作参考则标为下轮局部校正。scene_goal为当前场景短目标。完整数字模型只在故事演绎器用profile_updates进行有依据的稀疏更新；不注册任意字段/路径写入工具。

官方插件管道保留结构化 error.code/message；outcome_unknown 跨进程传递后仍为结果未知。官方插件按 ID 分别打包、安装和运行，确认窗口校验目标插件确切归档；停用/卸载终止目标运行进程，其他插件继续运行。包构建与分发详见 PLUGIN_SPEC.md 的“独立官方插件包”。
