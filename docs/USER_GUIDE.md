# 闪念 Shannon 3.0

一个简洁、轻量的 Windows 桌面 AI 搜索框。按下全局快捷键即可唤起，提问后以流式方式返回回答，用完按 `Esc` 隐藏，常驻托盘，随时待命。

基于 [Tauri 2](https://tauri.app) 构建，使用系统自带的 WebView2，常驻内存占用低；默认接入 DeepSeek，也可在配置文件中更换为其他兼容 OpenAI 接口的服务。

## 功能

- **第三方工具插件**：`/plugin install ZIP完整路径或HTTPS地址` 安装闪念 JavaScript 工具插件，确认来源和权限后启用。输入 `@` 选择插件或工具，再用自然语言描述需求；支持键盘补全、查询、启停、卸载及 AI 直调。开发规范与示例见 [PLUGIN_SPEC.md](development/PLUGIN_SPEC.md)。
- **AI 直调工具**：自然语言创建、安排日期、排序、删除和恢复便签，或打开计时设置。普通对话和联网搜索共用同一工具目录；模型及接口需支持工具调用。后续开发遵循 [AI_TOOLS.md](development/AI_TOOLS.md)。
- **可选本地语音输入**：输入 `/voice install` 安装组件后，在搜索输入框内长按鼠标左键约650毫秒，使用 SenseVoiceSmall INT8 在 CPU 上离线识别，按停顿分句出字，背景涟漪表示正在听。松开左键或 Esc 结束并完成最后一句；拖动选字不触发，文字不会自动发送。无需 API Key，音频不上传。

AI 便签技能位于 [`skills/shannon-notes`](../skills/shannon-notes/SKILL.md)，支持创建、列出、展开、完成和恢复便签。运行包含此接口的新版闪念后，AI 可通过技能内的 Python 脚本调用；无需模拟键盘或联网。

- **纸笺便签**：`/note 买牛奶` 或 `/便签 买牛奶` 添加待办，`/note` 或 `@note` 展开。收起后是小图标，点击展开、Esc 收起，按住拖拽可磁吸屏幕四边，放在中间则成为浮球，位置会记住。点击文字划去/恢复；点击日期文字安排或修改日期（无日期时显示“未安排日期”），删除按钮移入“最近删除”，可撤销或恢复；拖动条目左侧把手调整顺序，把手聚焦后也可用 ↑↓ 排序。AI 同样支持这些操作，例如 `@note 把买牛奶安排到明天`、`@note 删除买牛奶`、`@note 把写报告放到第一项`。日期只作日程标记，不触发通知；× 或 `/note --close` 退出并保留数据。

- **即用即走**：`Alt`+`Space` 唤起或隐藏，失去焦点时自动隐藏；唤起时自动填入其他程序中选中的文字
- **@ 内置工具**：`@note 记下买牛奶`、`@clock 设置5分钟倒计时`，也支持 `@便签`、`@计时器`。单独发送 `@note` 或 `@clock` 可直接打开对应界面，无需经过 AI。
- **对话**：流式输出、Markdown 渲染、代码高亮与一键复制；支持深度思考与联网搜索；对话记录保存在本地
- **数学公式**：回答及思考内容支持 `$…$`、`\(…\)` 行内公式和 `$$…$$`、`\[…\]` 独立公式，可显示分式、积分、矩阵与对齐公式。字体随应用打包，离线可用；过宽公式在内容区内横向滚动，代码块和普通金额保持原样。
- **打开应用与文件夹**：`/o 名称` 打开应用、文件夹、文件或网址，支持拼音与首字母匹配；`/rmbr` 管理别名
- **系统提示词**：`/spt 序号` 切换预设的回答风格，内置「默认」「翻译」「润色」，可自行添加
- **模型选择**：设置中直接选择 V4 Flash 或 V4 Pro，保存后从下一次请求生效，普通对话、角色聊天和故事舞台共用；深度思考单独开关。Flash 使用官方当前模型名 `deepseek-flash`，Pro 使用 `deepseek-v4-pro`。已有自定义模型保持显示，接口地址继续沿用配置，不会被切换模型覆盖。
- **命令提示**：输入 `/` 显示命令列表，参数提示随输入实时更新
- **顶部计时器**：`/clock` 打开计时设置，`/clock up` 正计时，`/clock 5m` 倒计时；已有计时器时会提示并补全 `/clock restart`，确认后重新设置。设置支持左右键切换、回车开始、Esc 退出；时长编辑中到达光标右边界后再按右键可切换正计时。开始后贴在屏幕顶部中央，悬停可暂停、重新开始或关闭。
- **节日主题**：按日期自动启用节日外观；节日主题在线推送，无需更新版本；支持自定义主题（见 [THEME_SPEC.md](development/THEME_SPEC.md)）
- **配置文件**：全部设置集中于带说明的 `config.toml`，`/config` 打开，保存后立即生效
- **在线更新**：自动检查新版本，`/update install` 下载并安装，安装包经签名校验

在闪念中输入 `/?` 可查看完整的快捷键与命令说明。

## 下载插件（试用）

输入 `@下载` 或 `@download` 打开下载窗口；`@下载 https://example.com/file.zip` 可离线准备任务，无需 AI。首次在窗口点击安装按钮，同意后从上游 GitHub 安装 Gopeed 1.9.3 Windows x64 后台组件（约38.5 MiB），校验 ZIP 和程序 SHA-256；默认安装包不包含引擎。组件许可和源码见 [third_party/gopeed/NOTICE.md](../third_party/gopeed/NOTICE.md)。

普通 HTTP(S) 文件保存到系统“下载”目录下的 `Shannon/`，目前不开放任意路径、请求头、网页解析或脚本。添加下载须用户在独立窗口确认，最多4个连接、最多3项同时下载；是否比浏览器更快取决于服务器，自动测速尚未实现。AI 可准备任务、查询、暂停、继续和取消任务，不能自行批准下载或安装。取消只移除任务，保留文件；相同链接有任务时复用，不重复创建。

关闭下载窗口会继续后台下载；正常退出整个应用先暂停并关闭独立引擎，下次打开下载窗口载入任务后可继续。组件与任务数据库位于本地应用数据目录 `components/gopeed/1.9.3/`，不混用个人已安装的 Gopeed。链接失效、应用被强制结束或不支持续传时仍可能需要重新下载。速度、进度、筛选及任务操作使用闪念自己的界面。

开发验证：`node --test tests/downloads.test.js`、`cargo test --offline --manifest-path src-tauri/Cargo.toml download`。真实引擎回归 `python tests/gopeed-smoke.py` 使用 `release/components/gopeed-web-v1.9.3-windows-amd64.zip`，只在 `release/` 内创建样例文件，验证本机鉴权、暂停、重启续传、字节一致性与取消保留文件。

## 安装

在 [发行版](https://gitee.com/wu-dinglin/shannon/releases) 下载最新的 `Shannon_<版本号>_x64-setup.exe` 并运行。

首次唤起后，在设置面板中填写 [DeepSeek API Key](https://platform.deepseek.com/api_keys) 即可使用。

系统要求：Windows 10 / 11（x64），需安装 WebView2 运行时（Windows 11 已自带；Windows 10 安装程序会自动下载）。

## 数据与隐私

- 配置、对话记录与输入历史均保存在本机 `%APPDATA%\com.brynn.ailauncher\`，不上传至任何服务器
- 提问内容仅发送至配置文件中指定的 AI 接口
- 闪念定期访问本仓库检查新版本与在线主题，请求中不包含任何个人数据；可在配置文件中分别关闭
- API Key 以明文保存在本机配置文件中，请勿外传该文件

## 本地手势鼠标

输入 `/gesture help` 查看全部操作，`/gesture start` 后台开启，`/gesture status` 查询，
`/gesture stop` 关闭并释放摄像头，`/gesture preview` 打开预览（默认暂停）。支持 `/手势` 前缀。
`/gesture cameras` 列出设备，`/gesture config hand Left` 等命令保存配置，`/gesture restart` 应用。
先输入 `/gesture install` 安装组件。接口经 Rust 后端调用组件自带的便携 Python，不发送给 AI 服务；用户无需安装 Python 或运行 setup.ps1。默认不读取开发机项目路径。开发者可显式设置 `GESTURE_MOUSE_HOME` 使用外部项目。


### 手势状态悬浮窗

开启手势识别后自动显示顶部状态小岛，沿用计时器的深色和橙色图标；
显示识别到的捏合、挥手、滚动，以及暂停、等待、设备异常等状态。
悬停展开摄像头、FPS、暂停/继续和关闭按钮；关闭识别后小岛自动收起。
计时器同时使用时自动错开位置。闪念运行时，也能显示和控制手动 run.cmd 打开的识别窗口。

两个组件都安装且手势唤醒后，握拳并稳定约半秒，会自动唤起搜索框进行本地语音输入；保持握拳说话，松拳结束并补全最后一句。Esc、手势关闭、失去追踪或摄像头断开也会结束，不自动发送文字。右摆切换下一曲无需特定手掌或手背朝向。组件已包含此行为；使用外部开发项目时才需运行 `npm run install:gesture-voice`。

便签默认查看“今天”：未安排日期、今天及未完成的逾期项目会显示；未来项目从“以后”查看，“全部”保留完整列表。日期快捷安排提供今天、明天、后天及随后五个周一至周五日期（不计算节假日调休），也可手选任意日期。图标数字统计今天尚未完成的项目。

便签展开时可按住顶部标题空白区域拖动，使用四向箭头光标；不会触发收起，也不影响条目排序、日期和标题按钮。收起后图标会跟随新的位置。

便签顶部显示当天日期和星期，跨日自动更新。默认鼠标移开 4 秒后收起，移回取消；编辑日期、查看最近删除、拖动或保存时暂缓。顶部图钉可固定展开、关闭自动收起，选择会记住；固定后仍可手动收起。

AI 支持 `@note 删除所有便签`：查询真实 ID 后一次批量移入“最近删除”，包含已完成与未来日期项目，可恢复；不会逐条调用而触发工具数量上限。本地桥接也支持 delete_many（ids）。

## WeChat 模拟聊天

输入 `@wechat 小林` 或 `@微信 小林`，打开与指定姓名的 AI 伙伴聊天的手机竖屏微信风格窗口（默认390×720），可拖动顶部移动；姓名必填。也可用 `@wechat/open {"peer_name":"小林"}`，或让 AI 帮你打开。使用现有 AI 配置，需先填写 API Key。生成期间顶部显示“对方正在输入...”，完成后一次显示回复；支持Enter发送、Shift+Enter换行，聊天记录按姓名保存在本地。该功能为内置工具插件，无需安装ZIP，不连接真实微信。

微信模拟聊天自动使用 prompts.toml 中的 `[4]` 提示词，每次发送时读取最新内容；支持 `{date}`、`{weekday}` 和 `{peer_name}` 占位符。不会修改主搜索框的提示词选择；缺少提示词4或文件格式错误时会明确提示。

微信聊天右上角“…”进入人物设定：角色卡涵盖主控角色、AI核心性格与状态、历史影响、双方关系、世界背景、开场时间地点、关键NPC、禁忌边界和开场情境。首次可“保存并开场”，将设定作为开场上下文发给AI；后续修改下一轮生效。故事报告可查看或手动修订时间、角色状态、事件、记忆、伏笔与成长记录。每6个成功回合要求规则自检及压缩记忆，“系统提醒”额外触发自检。旧聊天记录自动兼容；设定、报告、回合数与对话保存在同一文件中，主搜索框提示词不改变。

微信角色扮演支持 `[]` 旁白约定：括号外为人物聊天，括号内可写动作、环境、时间切换或模拟附件，例如 `[第二天早上]`、`[一张小狗的图片，小狗是白色卷毛，戴蓝色项圈]`。AI 同样使用此写法；故事报告保留原有 `【】` 标题。附件描述仅代表剧情中的对象，不会生成真实文件或上传图片。

微信聊天左上角返回微信首页：最近聊天按最后成功对话排序，通讯录按姓名排列，点击即可继续各自的聊天、人物设定与故事报告；右上角 + 可创建人物。发现 → 朋友圈支持发布本地文字动态，内容保存在配置目录 wechat-moments.json；不会发送到真实微信；默认所有角色可见。各聊天未发送的草稿在当前窗口内独立保留。旧记录没有时间戳时按姓名排序，下一次成功聊天后更新排序。

朋友圈默认对所有已创建及后续创建的人物公开。聊天上下文带入最近24条公开动态（单条最多600字），不共享其他人物的私聊或人物资料。AI角色可通过聊天响应的moment字段发布一条自己的动态；该动态与成功聊天在同一会话文件原子保存。角色按主动生活设置自然更新，也可点击“看看朋友动态”：应用按最久未发布的角色轮换，单角色间隔至少10分钟，按其提示词4、角色卡、自己的报告及公开动态生成，仅接收经过长度验证的JSON正文，作者由应用确定。手动更新不推进聊天回合和报告；后台自主生成按主动生活设置执行；用户动态已保存而角色生成失败会单独提示，不重复发布用户动态。角色动态每人保留30条，合并列表最多500条。旧朋友圈缺少author时仍视为本人发布。

微信内置16款本地插画头像，角色卡中可选择更换，“我”页面可设置自己的头像。旧角色在读取时根据设定中的明确关键词匹配（如眼镜、银发、长发），无匹配则按姓名稳定分配；不依据姓名推断性别。Card.avatar 保存内置ID，服务端校验白名单；目录由 src/wechat-avatar-catalog.json 共用，图片在 public/avatars/，不接受任意图片URL或路径。聊天、通讯录和朋友圈显示同一角色头像，人物头像随原会话原子保存；本人头像在当前应用本地保存。头像只是显示资料，不改变角色设定。

微信通讯录中每位好友右侧提供删除图标，人物设定页底部也提供删除好友入口（最近聊天列表不再显示删除按钮）；应用内确认后，从列表及共享朋友圈隐藏，并停止该角色动态生成。通讯录底部“已删除好友”可恢复；聊天、人物设定、故事报告、头像和动态随原Session保留在同一文件中，deleted_at缺省0兼容旧记录，删除/恢复原子保存并与聊天共用REQUEST锁。删除当前人物后清理活动对象，仍可在首页选择其他人物；同名新建/主搜索框打开会要求先恢复，避免覆盖旧记录。此删除不向模型暴露自动执行能力。

删除确认框默认不勾选“同时删除聊天记录”，保留可恢复删除；勾选后明确显示不可恢复提示，确认将从会话文件移除整个人物的聊天、人物设定、报告及角色动态，不加入已删除好友。同名再次添加是新会话。此永久删除只允许微信窗口、与聊天共用锁，不开放给模型工具；应用在显示勾选项、对象姓名和影响范围后要求用户点击确认。按钮主色统一使用WeUI的#07C160和#FA5151。


## 局域网广播站

输入 `@broadcast` / `@广播` 打开内置广播站。可以在窗口填写标题、正文、有效期（1小时/1天/7天）和置顶，点击“预览并发布”后确认；或输入 `@broadcast {"title":"通知","content":"下午三点见","minutes":60}` 离线准备预览。自然语言 `@广播 帮我准备一条明天下午开会的通知` 使用统一AI工具目录。第三方ZIP暂不能创建原生窗口/监听网络，广播站与便签、计时器一样由宿主内置，不授予任意网络或Tauri权限。

在窗口确认“开启局域网共享”，绑定本机所选私有IPv4地址与系统分配端口；应用尝试填入主路由地址，多网卡/VPN时可手动修改为本机其他局域网地址。点击“复制链接”，同网络用户用浏览器打开，带访问码链接会自动进入，也可手工输入访问码。网页只读，每5秒更新，只显示未撤回且未过期广播。HTTP不做传输加密；访问码应只分享给预期读者。系统防火墙或Wi-Fi隔离可能阻止其他设备连接，应用不自动修改防火墙、路由器或配置端口转发。

共享默认关闭，重启不自动开放，关闭广播站窗口或点击“停止共享”即停止监听和连接；每次开启生成新的128位随机访问码，旧码不复用。广播内容保存在配置目录 `broadcast.json`，最多200条记录，每条标题1–100字、正文1–6000字、有效期1–10080分钟；发布后不可直接改写，撤回需确认。撤回/过期不删除本地历史，也不能收回读者已看过的内容。

AI工具：`broadcast_open`、`broadcast_status`、`broadcast_list`（最近30条摘要）、`broadcast_read({id})`、`broadcast_prepare({title,content,minutes?,pinned?})`、`broadcast_withdraw({id})`。先list获取真实ID；prepare/withdraw仅创建绑定确切内容或目标的10分钟预览，返回confirmation_opened，不代表已发布/撤回。只有broadcast窗口能读取确认令牌并调用确认、开启共享、停止共享；模型没有这些接口，额外confirmed字段拒绝。手动与AI复用公共业务函数；本地确认成功后原子保存才生效。

远端固定路由仅提供查看页、样式、脚本及鉴权后的广播JSON；不映射磁盘、不暴露聊天/便签/配置、没有写接口。不返回CORS许可，校验Host/Origin并拒绝重复头、请求体和非GET；头部最多4KiB、单连接8秒、并发32，关闭共享会中止连接。返回no-store、nosniff、no-referrer及限制脚本/连接为同源的CSP。访问码仅在本机窗口提供，AI状态接口不返回访问码；分享链接把访问码放在片段，查看页读取后清除地址中的片段，后续通过Authorization发送。

微信聊天使用直接回话模式：模型以JSON分别返回reply（可见聊天）、report（后台故事报告）和可选moment（朋友圈正文）。应用先解析并校验，再原子保存本轮聊天、报告及动态；聊天气泡和对话摘要仅使用reply，report的六轮自检/压缩记忆机制继续生效，可在人物设定查看。回复必须由角色以自己的口吻直接发消息，动作等仅在必要时用[]，不要求聊天正文写第三人称叙事。兼容模型直接返回普通聊天文字（保留[]叙述）；后台报告不完整时保留旧报告，记忆更新无效时不写入记忆，不阻断正常聊天。报告标题混入reply或结构化JSON截断时仍不保存，草稿保留。历史消息及完整协议保留，最新规则明确旧叙事格式不再用于聊天正文。提示词4保持原文件不变，聊天交付规则在系统上下文末尾覆盖其冲突格式。


微信角色自然聊天与自主动态：角色卡新增说话习惯、口吻示例、兴趣和当前小目标；聊天完整生成后按空段落分成最多3个气泡，代码块和[]保留，不按字流式显示。用于模型的历史会跳过旧叙事报告回合，将新JSON响应中的可见文字还原为聊天示例；磁盘原聊天与完整协议不改写，其他provider工具/签名块保持原样。后台事实不在普通轮次携带完整旧报告样本，压缩轮才带入近期报告供汇总。

每个人物独立存储长期记忆：稳定key、类型、事实、原文依据、来源、时间、启用状态及最近8次旧版本。模型可在memory_updates中更新最多4条，每条fact最多300字；user来源必须逐字引用本轮用户文本，story来源须对应本轮生成的虚拟剧情，不能伪装为用户事实。整批校验后提交，与聊天、报告和朋友圈一起原子保存。使用本地双字片段匹配召回最多8条相关/重要记忆，不额外安装向量模型。“人物设定 → 记忆与日常”可修订、遗忘、恢复并查看虚拟日常；编辑绑定当前人物姓名，切换人物后拒绝误写。

原生后台调度随闪念进程运行，关闭微信窗口后仍可工作，退出闪念后停止。默认开启主动朋友圈和主动消息：启动后等待2分钟，每分钟检查；用户近2分钟操作、前台请求正在执行、23:00–08:00免打扰时跳过。私聊优先，每人私聊间隔默认15分钟、朋友圈间隔默认3小时，所有角色合计每日最多4次朋友圈生成、2次主动消息生成，每人朋友圈每天最多成功1次；无回应时同一角色不继续主动联系。生成尝试（包括休息、失败和取消）占调用额度，不为凑消息反复重试。新人物需已有聊天、性格或兴趣资料才参与；已删除人物排除。具体设置在“我 → 角色的主动生活”。

用户操作会取消等待中的后台网络请求，前台最多等待2秒获取同一REQUEST锁；后台单次90秒超时，生成前持久预留配额，避免重启绕过预算，OS文件锁防止多个进程同时后台生成。内容重复按去除标点/空白后的最近消息/动态抑制；模型允许休息，不强制发布。后台朋友圈不提供私聊原文、用户资料、长期记忆或完整报告，仅使用角色自己的公开字段、公开日常和朋友圈；公开日常只由实际发布的朋友圈推进，私聊不回写成公开生活。虚拟事件不代表真实外部平台操作，不发送真实微信消息或局域网广播。

新后台事件只刷新已打开微信窗口的相关聊天/列表/朋友圈，不强制弹窗；未读计数持久保存，进入聊天清除。自己发朋友圈后不再立刻触发另一位角色生成，角色由后台自然更新；“看看朋友动态”仍可手动请求即时生成。角色设置中可以单独暂停主动消息；直接发送完整句子“别主动找我”“不要打扰我”“停止主动联系”等会暂停该人物主动消息，“恢复主动联系”等恢复，引用这些句子不会改变开关。

全局策略和生成额度保存在配置目录wechat-social.json；每个人物的memories/social随原wechat-chats.json保存，旧数组/旧Session可兼容读取。新增Tauri入口仅wechat窗口可调用，后台与手动调用复用业务模块和现有AI协议，不开放任意脚本、任意路径或任意Tauri调用。实现参考dafeiyu-astrbot的机制设计，未引入其AstrBot/Python运行依赖或复制第三方插件代码。

微信朋友圈支持点赞、取消点赞和评论；用户、当前角色及其他角色均可互动，角色在聊天和后台日常中自行决定。互动身份由应用分配，不能代替其他人。每轮最多3项角色互动，每条评论最多500字；重复点赞和相同评论不重复保存。朋友圈上下文明示实际发布者及是否为当前角色本人，优先于旧报告和记忆。头像选择位于独立二级菜单（我页面与人物设定均可进入），不再在设置中铺开。

朋友圈评论支持定向回复：点击评论后输入回复，以“甲 回复 乙：正文”展示，原评论与回复均保持平铺的微信式样式。角色在聊天或现有后台主动任务中，依据性格、关系和评论内容自行决定回复或保持安静；沿用已有免打扰、频率及额度设置，不保证即时或每条必回。同一角色不会重复自动回复同一条评论。旧评论记录自动兼容。

角色主动私聊现优先于朋友圈，独立间隔默认15分钟（可设5分钟至1天），不受朋友圈3小时冷却阻挡；启动或窗口操作后空闲2分钟检查。每日已有额度、免打扰、暂停和未回复限制仍保留；旧设置迁移不改原每日额度。角色可保存下一次想聊的话题供聊天/主动消息延续，私有话题不提供给公开朋友圈任务。

微信发送后的回复任务由闪念后台持有，返回列表或关闭微信窗口不会取消；可重新打开查看正在输入状态、完整回复或失败原因。任务绑定发送时的人物，切换对象不会串话；回复完成更新未读，失败保留本轮原文供重试。其他人物的回复任务串行处理，修改人物设定等写操作仍避开生成期间以保持记录一致。需保持闪念主进程运行，退出应用后不继续生成。

角色聊天支持按语境选择1–4条独立消息或有意静默（messages数组、silent标志），旧reply格式仍兼容。应用保存实际消息，不把静默当发送失败或展示空白气泡，静默仍保存用户本轮消息。角色依据语气、关系、情绪线索调整回应，不固定每轮追问或安慰，不通过沉默惩罚或操控；静默后至少等待一个私聊间隔再允许主动联系，避免立即打断用户需要的空间。此处是虚拟角色的行为选择，不代表真实意识。

故事报告更新与模型格式成功解耦：每次成功完成聊天（含有意静默）记录一轮。完整模型报告按原规则保存；仅六轮自检/压缩字段缺漏时保留完整故事字段并补充事实归档；报告缺失时按双方实际消息生成事实记录，沿用已确认状态，不臆造剧情。每6轮形成近期对话摘录归档，事件/归档有长度上限，滚动保留最新内容。人物设定显示本次更新来源与缺漏说明，并可查看规则自检；程序记录检查会明确标注，不冒充模型完成的规则自检。只对更新后完成的聊天计数，不追溯改写旧聊天。

头像二级菜单支持上传本地PNG/JPG/WebP（最大10MB），预览并手动拖动、缩放裁切为256×256正方形后确认。自己和角色均可使用；角色选择后沿用人物设定的保存操作。头像在本地wechat-avatars目录按内容哈希保存，重启后保留，不上传到模型或外部服务。应用只接受有上限、可完整解码的静态PNG，固定头像编号不接受外部URL或任意文件路径。

上传头像后可直接拖动图片选择区域，通过缩放条或滚轮放大，方向键微调（Shift加速），并可一键重置。裁剪区域始终被图片覆盖，辅助网格不写入最终头像；取消或重新选图时释放图片资源。

朋友圈支持聊天事件驱动：角色在每轮对话中可依据自身性格、情绪变化和分享意愿，当下填写moment发布，不等待后台间隔，也可与有意静默同时发生。后台定时生成的开关、间隔和额度只控制后台任务。聊天发布后立即刷新朋友圈提示，并由应用记录真实作者及发布事实，避免仅在模型报告里声称发布。情绪不是强制触发器，不公开私聊隐私，不为发布虚构经历。

## 故事舞台

搜索框输入 `@story` 或 `@故事` 打开独立故事舞台。创建故事，设定世界、你主控的人物和初始AI人物（也可留空让人物随剧情登场）；也可从现有微信人物复制资料。主界面展示叙事、当前场景、人物状态与目标、已发生事件和角色微信记录。写下你的行动，点击“继续演绎”；生成在后台进行，关闭窗口也能继续，完成后保存。

微信是人物工具之一。角色可联系故事中的其他人物或你的角色，也可发布朋友圈、回复或不回复；实际动作保存为工具事件，并成为后续剧情上下文。点击“打开角色微信”可在原微信插件中查看；最近聊天中也可进入故事通信记录。故事内通信不会发到真实微信，也不混入旧私聊。角色卡可随剧情新增、离场、退场和回归；性格、心理、状态、目标、描述与关系均可发展。性格和登退场变化需有剧情原因，并保留人物变化记录。角色姓名作为历史通信身份保留，不因退场而删除；不代写用户主控角色的心理或决定。

支持保存、切换多个故事和主搜索框AI直调（story_open/list/read/create/update/advance/wechat）。一个故事最多200轮、1000条工具记录，最多50个故事；不提供不可恢复删除入口。生成使用现有AI接口，API请求带有故事资料、近期叙事、事实账本和本故事通信记录；不导入旧微信私聊。失败有明确原因，不保存半个回合；重试前可先查询状态。

在故事人物的微信视图中，你也可以以主控角色的身份直接发消息，发送后触发后续演绎；角色是否回复由剧情、性格与当前状态决定。代表用户发送的入口仅供本地微信界面使用，不开放给AI冒充用户。消息已保存但生成启动失败时会明确提示已发送，避免重复提交。

动态人物卡：present在场、away暂时离场（仍可远程通信）、archived退出当前故事（保留档案，回归后才继续主动通信）。每轮最多新增4人，最多12人在场、总档案100人。人物变化面板记录登退场、性格和心理的前后状态与原因；编辑设定可以新增人物，将旧人物移出名单会归档而非删除。心理活动是虚构角色的感受、顾虑与想法，不是模型内部推理，也不会自动成为其他人物已知信息。

故事列表旁可“删除故事”，核对标题和轮数后移入“最近删除”；可从最近删除恢复完整剧情、人物、记忆及虚拟微信记录。删除当前故事会自动切换到其他故事，删完后回到空舞台。演绎中禁止删除，故事发生新变化后须重新确认。AI只能申请打开确认界面，不能自行确认；恢复复用公共业务函数。已删除的故事不参与普通列表、演绎及角色微信渠道，新故事不会复用它们的ID。

每轮演绎成功前会保留一个完整回退点。可“撤回上一轮”并取回原输入编辑，或在最后一轮点“编辑并重新演绎”；人物状态、底色、记忆、事件和角色微信一起回退。“恢复撤回”可找回原结果，新演绎成功后替换回退点。生成中不能回退；若之后手动修改设定、记忆或发送消息，旧回退点停用，避免覆盖这些修改。只保留最近一轮，不无限累积；升级前的旧轮次没有回退点，从升级后的下一轮成功演绎开始可用。

人物资料分为稳定性格/长期动机与当前心理/眼前目标。普通对话默认只更新临时状态，稳定人设的模型更新需明确标记长期变化并说明重要经历；底色可留白，并从用户逐渐补充的反应、台词、背景与创作期望中归纳形成；人设补充须引用本轮用户原文，开局背景也可用于补全仍为空的底色字段，但不能覆盖后续塑造的内容；不能用AI自己演出的情绪作为依据。用户新修订优先于旧推断，补充时保留无关的已有特点；手动修改角色卡也会更新底色。角色卡可填写不同场合的说话示例。明确换场、跨日或活动结束时，上一场心理与眼前目标收起；临时记忆（scope=scene）停用但不删除，长期约定和关系继续保留。旧存档缺少这些字段时直接兼容，不自动删除旧记忆或改写原始剧情。

故事长期记忆：演绎会从全部已保存剧情、事件、微信通信和人物变化中检索旧事，不限最近12轮。未完成约定和伏笔、手动标记的重要记忆持续带入；其他条目按当前话题和人物目标检索。角色记忆标记亲历/听闻/猜测，私聊及心理变化原文仅供相关人物回忆，公开动态标明只是可查看。旧故事的已有档案可直接查询，无需重建。

舞台右侧“记忆”支持按知情人查看、搜索全部往事、修订、标记完成或作废。条目带原文出处，保留最近8个旧文本版本及引用链；用户修订优先于自动提取，旧证据不能覆盖较新记录。已完成/已修订的记忆会在相关旧引文旁注明后续状态，避免把旧约定重新当成未完成。每轮最多16条结构化提取，最多2048条记忆、128条常驻重要条目，到上限会提示并保留已有条目，不自动删除；原文仍保留在原故事档案。检索为本地文字相关度与重要性排序，不需额外模型或向量服务，不意味着模型绝对不会漏用资料；导演视角仍可见全局，人物知情约束不等于独立安全隔离。

## 插件管理界面

设置中的“插件管理”、托盘菜单或 `/plugin` 可打开独立管理窗口。支持搜索和按已添加/内置/第三方/可添加筛选，统一管理便签、计时器、微信模拟聊天、故事舞台、广播站、下载、语音输入、手势控制，以及第三方工具插件。内置功能可添加、停用、移除后再添加；移除只注销入口和后续调用，数据与已下载组件保留，不删除程序文件，也不自动中断已开始的任务。相关窗口或设备正在使用时须先关闭或停止。

第三方插件可在界面填写ZIP完整路径或HTTPS地址安装，原有来源、权限、校验与确认流程保留；卸载保留独立数据。内置状态保存在 `builtin-plugins.json`，重启仍有效；移除/停用的功能从命令提示、@目录及普通/联网AI工具目录隐藏，旧AI调用在执行前重新校验。`/plugin list`仍返回第三方插件文本列表，`/plugin help`查看命令。管理入口不能被插件自身移除。

### 官方插件不随安装包预装

发布版主程序与插件实现分离，首次安装没有已添加的官方插件。添加时在确认窗口核对开发者、功能、版本、Gitee来源和校验信息；确认后下载共享插件运行包，后续插件复用。每个插件独立启停和保留数据。语音与手势仍需可选模型/环境，不会因为添加插件自动打开设备。第三方插件继续使用原有ZIP格式、权限确认和开发者信息。

正式发布请使用 `scripts/build/release.py`；开发插件时使用 Cargo feature `native-runtime`，默认构建为无插件实现的核心主程序。完整插件测试用 `cargo test --features native-runtime`，核心测试用默认 `cargo test`。插件Schema与元数据是目录资料，保留在主程序中；插件执行代码和独立窗口只在 Gitee 插件包中。

官方插件离线添加：在“添加插件”的“本地官方插件包”填写本版本 `official-runtime-版本-windows-x64.zip` 的完整路径，再点目标官方插件的“添加”并确认。留空则从Gitee下载。官方共享包不要放进第三方插件安装框；导入前后均核对当前目录的大小与哈希，不执行任意ZIP或其他版本的运行包。

故事人物使用固定容量的混合人设：六项0–100创作倾向（社交、直接、自律、温和、好奇、稳健），最多6项说话标签、8条各48字的背景/例外，以及按对象分开的信任/熟悉/戒备和临时情绪。未确定的维度保持未知，不默认50。模型以稀疏补丁更新，没提到的特点保持不变；自然成长单轮最多3点，同维度6轮内不重复，重复依据不反复加分。用户明确修订不受步长限制。换场只清理情绪，关系和底色保留。旧文字本地留档，首次有依据时整理为紧凑模型；模型更新格式有误时保留原模型，剧情正常保存。角色设置保存时不会清空数字模型，修改创作参考后下轮局部校正。

模型上下文只带有上限的当前人设，成长依据与完整档案保留本地。回忆的提示视图限制条数与片段长度，完整历史及手动记忆搜索不截断原始存档。角色卡可查看数值和标签；数值只是演绎倾向，不是心理测评或强制行为规则。

本地插件更新：重新生成官方运行包后，运行与新校验目录匹配的新版主程序，在“添加插件”填写本地官方ZIP路径，对故事舞台点“更新 / 启用”，无需先删除故事或卸载插件。
